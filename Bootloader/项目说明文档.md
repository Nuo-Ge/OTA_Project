# STM32F103C8T6 Bootloader 项目说明文档

## 文档信息

| 项目名称 | STM32F103C8T6 Bootloader（离线 OTA 固件升级） |
|---------|-----------------------------------------------|
| 主控芯片 | STM32F103C8T6（Cortex-M3，64KB Flash / 20KB SRAM） |
| 开发环境 | STM32CubeMX + CMake + ARM GCC |
| 文档版本 | V1.0 |

---

## 1. 项目简介

本项目是一个运行在 **STM32F103C8T6** 上的 Bootloader（引导加载程序），核心职责是：

1. **检测并校验**内部 Flash 中是否存有合法的用户应用程序（App）；
2. 在满足条件时**安全跳转**到 App 运行；
3. 支持**离线 OTA 固件升级**：从外部 SPI Flash（W25QXX）中读取新固件，搬运到内部 Flash 的 App 分区，并用 CRC32 校验完整性；
4. 通过外部 EEPROM（AT24CXX）持久化升级控制信息；
5. 通过 0.96 寸 OLED 显示屏实时显示启动状态与升级结果。

**定位说明**：本 Bootloader 只负责「搬运 + 校验 + 跳转」，不负责固件接收。新固件需由上位机或通信模块预先写入外部 W25QXX，升级控制信息写入 AT24CXX。

## 2. 系统总体设计

### 2.1 硬件组成

| 器件 | 型号 | 接口 | 作用 |
|------|------|------|------|
| 主控 | STM32F103C8T6 | — | 运行 Bootloader |
| 外部 Flash | W25QXX | SPI1 | 存放待升级固件镜像 |
| EEPROM | AT24CXX | I2C1（硬件） | 存放升级控制信息 |
| OLED 显示屏 | 0.96 寸 SSD1306 | 软件 I2C（PB8/PB9） | 状态显示 |
| LED | — | PA1 | 状态指示 |

### 2.2 引脚分配

| 引脚 | 功能 | 配置 |
|------|------|------|
| PA1 | LED | 推挽输出 |
| PA4 | W25QXX 片选（CS） | 推挽输出 |
| PA5 / PA6 / PA7 | SPI1_SCK / MISO / MOSI | 复用推挽 / 输入 / 复用推挽 |
| PB6 / PB7 | I2C1_SCL / SDA（AT24CXX） | 复用开漏 |
| PB8 / PB9 | OLED_CL / OLED_DA（软件 I2C） | 开漏输出 |

### 2.3 内部 Flash 分区

STM32F103C8T6 拥有 64KB 内部 Flash（`0x08000000 ~ 0x08010000`），分区如下：

```
0x08010000 ┌──────────────────────┐ ← FLASH_END_ADDR
           │      App 区          │
           │      (40KB)          │  APP_MAX_SIZE = 40KB
           │                      │
0x08006000 ├──────────────────────┤ ← APP_ADDRESS（偏移 24KB）
           │    Bootloader 区      │
           │      (24KB)          │  BOOTLOADER_SIZE = 24KB
           │                      │
0x08000000 └──────────────────────┘ ← BOOTLOADER_ADDR
```

### 2.4 外部存储分配

| 器件 | 地址区间 | 用途 |
|------|----------|------|
| W25QXX | `0x000000 ~ 0x0FFFFF`（1MB） | 固件镜像存储区 |
| AT24CXX | `0x00 ~ 0x0F`（16 字节） | 升级控制信息 `OtaInfo_t` |

## 4. 核心机制详解

### 4.1 启动流程

```
上电复位
  → HAL_Init()                    初始化 HAL 库与 SysTick
  → SystemClock_Config()          配置系统时钟 72MHz（HSE×9）
  → MX_GPIO_Init() / MX_I2C1_Init() / MX_SPI1_Init()
  → System_Init()                 初始化 AT24CXX 与 W25QXX
  → OLED 显示 "Bootloader v1.0"
  → OtaBoot_CheckAndApply()       检查并执行 OTA 搬运
  → Boot_CheckApp(APP_ADDRESS)    校验 App 合法性
  → Boot_JumpToApp(APP_ADDRESS)   跳转到 App
```

### 4.2 App 合法性校验（boot_jump.c）

Bootloader 通过检查 App 区首地址处的 **ARM Cortex-M3 向量表**来判定 App 是否合法：

```
App 区首地址 + 0x00 → 初始栈顶地址（MSP）
App 区首地址 + 0x04 → Reset_Handler 入口地址
```

校验条件：

| 检查项 | 条件 | 不满足时的结论 |
|--------|------|----------------|
| 栈顶地址 | 必须落在 SRAM（`0x20000000 ~ 0x20004FFF`） | App 非法 |
| ResetHandler | 必须落在内部 Flash（`0x08000000 ~ 0x08010000`） | App 非法 |

具体实现通过位掩码判断：`(stack_top & 0x2FFE0000) != 0x20000000` 即认为栈顶非法。

### 4.3 安全跳转流程（boot_jump.c）

跳转到 App 前必须完成以下 6 步，否则 App 可能运行异常：

| 步骤 | 操作 | 目的 |
|------|------|------|
| 1 | `__disable_irq()` | 关闭全局中断 |
| 2 | 清零 SysTick（CTRL/LOAD/VAL） | 防止跳转后 SysTick 中断跑飞 |
| 3 | 清空 NVIC 的 ICER/ICPR（8 组寄存器） | 清除所有中断使能与挂起标志 |
| 4 | `SCB->VTOR = app_addr` | 向量表重映射到 App |
| 5 | `__set_MSP(栈顶地址)` | 设置主栈指针为 App 栈顶 |
| 6 | 函数指针跳转到 Reset_Handler | 进入 App |

### 4.4 OTA 升级流程（ota_boot.c）

```
1. 从 AT24CXX 读取 16 字节 OtaInfo_t
2. 校验 magic == 0xA5A5A5A5 且 flag == READY
   ├─ 不满足 → 返回 IDLE（无升级任务，正常启动）
   └─ 满足 → 继续
3. 校验 total_size 合法性（0 < size ≤ 40KB）
   └─ 非法 → 返回 ERR_CRC
4. 擦除内部 Flash App 区
   └─ 失败 → 返回 ERR_ERASE
5. 分块搬运（每块 256 字节）+ 流水线 CRC32 计算
   W25QXX 读 → 内部 Flash 写 → CRC32 增量更新
   └─ 写入失败 → 返回 ERR_WRITE
6. CRC32 比对
   └─ 不匹配 → 返回 ERR_CRC（保留 flag=READY 供重试）
7. 清除 flag（写 AT24CXX flag=NONE）
   → 返回 SUCCESS
```

**关键设计点**：
- **256 字节分块**：匹配 W25QXX 页大小，且为偶数，满足内部 Flash 半字写入要求；
- **流水线 CRC**：边搬运边计算，无需二次遍历读回；
- **失败保留标志**：CRC 失败时不清除 flag，下次上电可自动重试。

### 4.5 升级控制信息结构体

```c
typedef struct __attribute__((packed)) {
    uint32_t magic;          // 0xA5A5A5A5（魔数）
    uint8_t  flag;           // 0x00=无任务，0x01=待升级
    uint8_t  reserved[3];    // 保留（补齐对齐）
    uint32_t total_size;     // 固件总字节数
    uint32_t total_crc32;    // 整包 CRC32 值
} OtaInfo_t;                 // 共 16 字节
```

### 4.6 CRC32 校验算法

采用与 zlib / 以太网 / PNG / ZIP 一致的标准 CRC32：

| 参数 | 值 |
|------|-----|
| 多项式 | `0xEDB88320`（反射形式） |
| 初始值 | `0xFFFFFFFF` |
| 输出异或 | `0xFFFFFFFF` |
| 测试向量 | `CRC32("123456789") = 0xCBF43926` |

提供增量 API：`CRC32_Start() → CRC32_UpdateBlock() → CRC32_Final()`，适合 OTA 流式校验。采用逐比特法而非查表法，以节省 64KB Flash 中的查表空间。

## 6. 使用说明

### 6.1 构建

```bash
# 配置（Debug）
cmake --preset Debug

# 编译
cmake --build build/Debug

# 或使用 Release
cmake --preset Release
cmake --build build/Release
```

编译产物：
- `build/Debug/Bootloader.elf` — 可执行文件
- `build/Debug/Bootloader.map` — 链接映射文件

### 6.2 触发 OTA 升级步骤

1. **写入固件到 W25QXX**（从地址 `0x000000` 开始）；
2. **写入控制信息到 AT24CXX**（从地址 `0x00` 开始，共 16 字节）：
   ```c
   OtaInfo_t info = {
       .magic      = 0xA5A5A5A5,
       .flag       = 0x01,            // READY
       .total_size = firmware_size,   // 固件实际字节数
       .total_crc32 = crc32_value     // 整包 CRC32
   };
   BSP_AT24CXX_Write(0x00, (uint8_t*)&info, 16);
   ```
3. **复位 MCU**，Bootloader 自动检测并完成搬运。

### 6.3 OLED 显示状态说明

| 显示内容 | 含义 |
|----------|------|
| `Bootloader v1.0` | 启动成功 |
| `OTA Update OK!` | 升级搬运校验成功 |
| `Error: Erase` | App 区擦除失败（死循环） |
| `Error: Write` | 内部 Flash 写入失败（死循环） |
| `Error: CRC` | CRC 校验失败（死循环） |
| `No valid App / Wait for OTA...` | App 区无有效固件，等待升级 |
| `Jumping to App` | 即将跳转到 App |

## 7. 错误码汇总

### 7.1 OTA 搬运状态（OtaBootState_t）

| 枚举 | 含义 | 系统行为 |
|------|------|----------|
| `OTA_BOOT_IDLE` | 无升级任务 | 正常跳转 App |
| `OTA_BOOT_SUCCESS` | 搬运校验成功 | 显示成功，跳转 App |
| `OTA_BOOT_ERR_ERASE` | 擦除失败 | 显示错误，死循环 |
| `OTA_BOOT_ERR_WRITE` | 写入失败 | 显示错误，死循环 |
| `OTA_BOOT_ERR_CRC` | 校验失败 | 显示错误，死循环 |

### 7.2 Flash 操作错误码（BSP_FLASH）

| 宏 | 值 | 含义 |
|----|-----|------|
| `BSP_FLASH_OK` | 0 | 成功 |
| `BSP_FLASH_ERR_PARAM` | 1 | 参数错误（非对齐、越界、空指针） |
| `BSP_FLASH_ERR_ERASE` | 2 | HAL 擦除失败 |
| `BSP_FLASH_ERR_WRITE` | 3 | HAL 写入失败 |

## 9. 注意事项

1. **跳转前必须关闭全部中断并重置 SysTick**，否则 App 启动后可能进入 HardFault；
2. **内部 Flash 必须先擦除再写入**，且只能半字（2 字节对齐）写入；
3. **升级固件大小不能超过 40KB**（`APP_MAX_SIZE`），否则会被判定为非法；
4. **CRC 校验失败时不清除 flag**，确保下次上电可自动重试升级；
5. **AT24CXX 每次写页后需等待约 5ms** 的写周期；
6. **Bootloader 编译产物不能超过 24KB**，否则会覆盖 App 区。
